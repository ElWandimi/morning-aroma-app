# Path-based routing (e.g. example.com/checkout), not hash-based -- real Disallow rules below
# actually work here, since the server sees these paths in the request itself. This file used to
# say the opposite (hash-fragment routing, where Disallow can't match anything), which was true
# when written but went stale once the app migrated to real paths -- this replaces that outdated
# reasoning with the real rules it was describing as impossible.

User-agent: *
Allow: /
Disallow: /admin
Disallow: /checkout
Disallow: /journey

Sitemap: https://morning-aroma.com/sitemap.xml
# The main sitemap is real, static, and generated at build time (scripts/generate-sitemap.mjs) --
# genuinely can't include blog posts or Academy courses, since both are entirely database-driven
# and this build script has no database access. These two dynamic sitemaps (server-side, GET
# /sitemap-blog.xml and /sitemap-courses.xml in server/src/app.js) always reflect the actual,
# current set of published posts / real courses. On the backend's own real domain, not
# morning-aroma.com's -- a real, valid, standard practice (a sitemap's own domain doesn't have to
# match the site it lists, only the URLs it CONTAINS have to be real and correct, which these are).
Sitemap: https://upbeat-rebirth-production.up.railway.app/sitemap-blog.xml
Sitemap: https://upbeat-rebirth-production.up.railway.app/sitemap-courses.xml
